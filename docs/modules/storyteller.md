# Storyteller Module Documentation

## Overview

The Storyteller module is the core narrative engine of the application. It leverages a multi-agent system (MAS) built on LangGraph/LangChain to simulate a "Writer's Room" environment. It handles plot generation, character psychology tracking, and script-level editing.

## Architecture

### Multi-Agent System (Writer's Room)

The module uses a sophisticated agentic workflow:

- **Supervisor**: The central coordinator that routes tasks to specialist agents using a handoff system.
- **Router/Planner**: Determines the sequence of narrative tasks (premise, plot, beats, script).
- **Specialist Agents**:
  - **Premise Architect**: Generates and refines world bibles and series premises.
  - **Plot Architect**: Designs high-level story arcs and episode roadmaps.
  - **Character Psychology**: Tracks character metrics (valence, arousal, autonomy) and ensures consistent behavior.
  - **Devil's Advocate**: Challenges narrative decisions to avoid clichés and logical gaps.
  - **Writer**: Converges narrative beats into final script content.

### State Management

State is managed via `WritersRoomState` (defined in `src/domains/storyteller/graph/state.ts`), which acts as the "Blackboard" for the agentic team.

Key State Elements:

- `beatBoard`: Current sequence of storyboard/narrative beats.
- `characters`: Full psychological profile and state history for each key character.
- `seriesBible`: The source of truth for world rules, factions, and tone.
- `taskQueue`: Active objectives currently being processed by the MAS.

### Action-Reducer System

Changes to the state are committed through the `ActionExecutor` and `reduceAgentActions`.

- **Executor**: Handles history (undo/redo), consistency checks, and approval workflows.
- **Reducer**: A pure logic layer that merges specialist agent outputs into the central state, ensuring validated updates to complex nested objects (e.g., Factions, World Rules).

## Components

### World Bible Panel

A comprehensive interface for managing world-building data. It is decoupled using `BibleContext` and `useBible` to avoid prop-drilling across its sub-components:

- `BibleOverview`: Visual moodboard and logline.
- `BibleFactions`: Political and social power structures.
- `BibleCharacters`: Casting and character relationship tracking.

#### Bible Locking Mechanism

To preserve the creative "source of truth," the World Bible can be locked:

- **Rule**: When locked, all manual edits and AI-driven updates (e.g., from the Storyteller agents) are disabled for non-admin users.
- **Permissions**: Only authorized "Central Users" (admins) can toggle the lock status.
- **Agent Integration**: AI agents are instructed to respect the lock; if a user attempts to generate Bible content while locked, the agents will redirect the workspace focus to character or episode development instead.
- **State Constraint**: The `BibleContext` enforces a `isReadOnly` flag derived from the lock status and user permissions, which reactively disables UI controls across all sub-sections.

### Workflow Canvas

Visualizes the narrative flow, allowing editors to interact with beats generated by the AI agent team.

## Services

- **Gemini Service**: Interface for multi-modal LLM interactions.
- **RAG Service**: Knowledge retrieval for maintaining continuity across long-form narratives.
- **Visual Moment Service**: Generates image prompts and handles stable diffusion/DALL-E integrations for moodboards.

## Schemas

Core data structures are enforced via Zod schemas in `src/domains/storyteller/schemas/agent-schemas.ts`, ensuring agent outputs are reliably parsed and persisted.
