## Part 2 — Ground rules for every agent (binding — read before starting)

1. **Gates:** `npm run qualitygate:file -- <path>` after each focused edit; `npm run qualitygate:changed` every 5 completed todos; end of task `npm run typecheck` + `npm run lint` + `npm run test:unit`. Never full-repo `tsc` mid-task. **No E2E.** Many failures → `qualitygate:capture` + `.local/quality-backlog.md`, rescan every 5 fixes.
2. **Never bypass:** no `eslint-disable` for quality rules, no `@ts-nocheck`, no `as` (only `as const`), no `any`. Magic-string sets → `enum`. File limits 400 warn / 800 error; complexity 15/25.
3. **No bulk codegen on `src/`** (`node -e`, heredoc transforms) — incremental edits only, one extract per step (`.cursor/rules/refactor-discipline.mdc`).
4. **Boundaries:** domains never import each other; shared never imports domains/app; cross-domain code moves to `@/shared`. Deletions follow create → rewire → grep-zero → delete.
5. **Evals:** any prompt/model/scorer change → run the gating matrix in `docs/TESTING.md`; no scorer below baseline (`evals/results/pre-grrm-baseline.json` is the pre-migration snapshot; `latest.json` currently holds a partial deterministic run and must be regenerated with keys before use as a baseline).
6. **File ownership:** each phase below owns a disjoint file set. If you must touch another phase's file, stop and coordinate (the two known shared files — `eslint.config.js`, `src/domains/__tests__/domain-structure.test.ts` — are explicitly sequenced in dependencies).
