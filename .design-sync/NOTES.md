# design-sync notes — world-building-kit

Repo-specific quirks discovered during the first sync (2026-07-07).

## Repo shape

- This is a Next.js **app**, not a component package: no `dist/`, no shipped `.d.ts`, no Storybook.
  The DS surface is `src/components/` (shadcn new-york style, Radix + CVA + Tailwind).
- The bundle entry is the authored barrel `.design-sync/ds-entry.ts` (NOT a synth scan):
  a bare synth entry from `src/components/` pulled in app-coupled files (AuthProvider → Supabase,
  shell/* → Next runtime) and ballooned the bundle to 8.4 MB. The barrel keeps it ~950 KB.
- `package.json` had no `name`/`version` — added (`world-building-kit@0.1.0`, private) because the
  converter's package-root walk needs a named package.json. Also added a `types` field pointing at
  the generated declaration tree (below).
- `.d.ts` contracts are generated by `npx tsc -p .design-sync/tsconfig.dts.json` into
  `.design-sync/.cache/types/` (gitignored, regenerated by `buildCmd`). Without it every
  `<Name>Props` degrades to a `[key: string]: unknown` stub.
- CVA variant props (`variant`, `size`) are declared inside `class-variance-authority` and get
  dropped by the extractor's own-props filter → hand-written `cfg.dtsPropsFor` for **Button** and
  **Badge**. Label uses cva but has no variant axes.

## Scope decisions

- Excluded as app-coupled, not design system: `AuthProvider`, `LoginButton`, `AsyncStatusIndicator`
  (Supabase/router), `EntityPicker` (TanStack Query data fetching), `ErrorBoundary`/`ErrorBoundaryWrapper`
  (renders nothing / pulls shell), everything under `src/components/shell/`.
- **LiquidGlass excluded**: it imports `Liquid` from `@/domains/marketing`, which drags the whole
  marketing barrel (Next runtime + WebGL/three.js) into the bundle. If it's ever wanted, it needs a
  decoupled import path first.
- `TextEffects/TextEffects.tsx` exports two components: `LiquidDistortionText` and `MotionHighlight`
  (there is no `TextEffects` component).
- Flat shadcn compound exports (`DialogContent`, `CardHeader`, … 48 names) are `null`-excluded from
  the card list but remain importable from `window.WorldBuildingKit` (78 exports total) and are
  taught through the authored previews.

## Styling / fonts

- The app is **dark-first**: `globals.css` `:root` holds dark HSL tokens; there is no `.dark` class
  toggle. `h1–h6 { @apply font-mono }` (JetBrains Mono headings) is the intentional brand look —
  do not "fix" mono titles.
- Component CSS is compiled at sync time: Tailwind CLI over `src/app/globals.css` with
  `.design-sync/tailwind.ds.config.js` (content = `src/components/**` + `.design-sync/previews/**`).
  New Tailwind classes used only in previews require re-running `buildCmd` before the converter.
- Fonts (Inter, JetBrains Mono, Syne) are loaded by `next/font` in the app; the bundle uses a Google
  Fonts `@import` (`fonts-header.css`) + `:root` `--font-sans/--font-mono/--font-syne` definitions
  (`fonts-vars.css`). Validate reports `[FONT_REMOTE]` — expected, not a miss.
- Previews render inside the product's white card chrome, so `cfg.provider = DsFrame`
  (`.design-sync/ds-frame.tsx`, shipped via `extraEntries`) wraps every story in the app's dark
  surface. Without it, ghost buttons and foreground text are invisible.

## Known render warns (triaged legitimate)

- `[FONT_REMOTE]` "Inter", "JetBrains Mono", "Syne" — remote font host by design (see above).
- BleedingText: `textColor`/`particleColor` apply to the animation phase, not the static fill —
  the default render shows the red "bleeding" treatment; custom colors look white in a static
  screenshot. Component behavior, not a preview bug.
- MotionHighlight / GlowEffect spotlight are hover-driven; static captures show the resting state.

## Re-sync risks

- `package.json` `types` points into gitignored `.design-sync/.cache/` — on a fresh clone the path
  is absent until `buildCmd` runs; run `buildCmd` before the converter (the driver does this).
- The Google Fonts `@import` fetches at render time; offline render checks would show fallback
  fonts without failing.
- The generated declaration tree uses `noCheck: true` — upstream type errors in `src/components/`
  won't block emit but could produce odd props; check `[DTS]` output after big component changes.
- Preview compositions reference app idioms (entity badge colors from `EntityPicker`, writers-room
  copy); if the product's domain language shifts, previews still compile but may read stale.
- `chromium-1200` (repo's Playwright pin) lives in `~/Library/Caches/ms-playwright` (macOS path —
  not `~/.cache`).
