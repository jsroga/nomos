Foundation

Typography

Our type scale is designed for clarity and hierarchy. Use semantic names instead of arbitrary pixel values.

Font Families

Primary

Inter

Used for all body text, headings, and UI elements.

font-family: 'Inter', system-ui, sans-serif;

Monospace

JetBrains Mono

Used for code, labels, and technical content.

font-family: 'JetBrains Mono', monospace;

Type Scale

Name Size Class Example Usage
Micro 9px text-[9px] TIMESTAMPS, METADATA Timestamps, tiny labels
Caption 10px text-[10px] SECTION LABELS Labels, hints, captions
Small 11px text-[11px] Small body text and descriptions Descriptions, secondary text
Base 12px text-xs Standard body text Body text, inputs
Medium 14px text-sm Emphasized body text Important content
Large 16px text-base Headings and titles Dialog titles, section heads

Best Practices

Do's & Don'ts

Learn from common mistakes. Follow these guidelines to maintain consistency across the codebase.

Typography

DO
// Use semantic class names <p className="text-[10px] font-bold uppercase tracking-widest"> LABEL TEXT </p> // Use established font sizes text-[9px] // Micro text-[10px] // Caption text-[11px] // Small text-xs // Base

Use consistent font sizes from the type scale.

DON'T
// Don't use random sizes <p className="text-[13px]"> Random size </p> // Don't mix weights inconsistently <p className="font-semibold">Some text</p> <p className="font-bold">Other text</p> <p className="font-extrabold">More text</p>

Avoid arbitrary font sizes and inconsistent weights.

Spacing & Borders

DO
// Use consistent border-radius <div className="rounded-lg"> // 8px <div className="rounded-xl"> // 12px <div className="rounded-2xl"> // 16px // Use spacing scale <div className="p-4 gap-3 space-y-4"> {/* content */} </div>

Stick to defined radius and spacing tokens.

DON'T
// Don't use arbitrary values <div className="rounded-[13px]"> <div className="p-[17px] gap-[5px]"> // Don't mix radius styles <div className="rounded-lg"> <div className="rounded-full"> <button className="rounded-md">

Avoid arbitrary spacing values and mixing radius styles.

Color Usage

DO
// Use semantic color combinations <div className="bg-white/5 border border-white/10"> <span className="text-zinc-300">Content</span> </div> // Use state colors consistently <div className="bg-green-500/10 border border-green-500/20"> <span className="text-green-400">Success</span> </div>

Match background, border, and text colors from same family.

DON'T
// Don't mix color families <div className="bg-blue-500/10 border border-green-500/20"> <span className="text-yellow-400">Mixed colors</span> </div> // Don't use too many opacities bg-white/3, bg-white/7, bg-white/13...

Avoid mixing unrelated color families. Stick to /5 and /10 for backgrounds.

Component Composition

DO
// Use existing components import { SidebarSection } from '@/components/ui/domain-sidebar' <SidebarSection title="Settings" icon={<Settings />}> <SidebarSliderRow label="Size" value={size} onChange={setSize} /> </SidebarSection>

Reuse existing components instead of recreating them.

DON'T
// Don't recreate components <div className="space-y-2 py-4 border-t"> <h3 className="text-xs font-mono font-bold"> Settings </h3> <div className="space-y-2"> <div className="flex justify-between"> <span>Size</span> <span>{size}</span> </div> <Slider value={size} onChange={setSize} /> </div> </div>

Don't rebuild what already exists. Check domain-sidebar.tsx first.

Layout & Structure

DO
// Use consistent spacing between sections <div className="space-y-8"> <Section /> <Section /> </div> // Group related controls <div className="space-y-4"> <SidebarLabel>Dimensions</SidebarLabel> <SidebarSliderRow label="Width" /> <SidebarSliderRow label="Height" /> </div>

Use space-y for vertical rhythm and group related items.

DON'T
// Don't use arbitrary margins <div className="mt-[23px] mb-[17px]"> <Section /> </div> // Don't scatter related controls <div> <SidebarSliderRow label="Width" /> <SomeOtherControl /> <SidebarSliderRow label="Height" /> </div>

Avoid arbitrary spacing and poor grouping of related controls.

Interactive States

DO
// Provide clear loading states {isGenerating && ( <div className="bg-indigo-500/5 border border-indigo-500/10 p-4"> <Loader2 className="animate-spin" /> <span>Generating... {progress}%</span> <Progress value={progress} /> </div> )} // Disable during operations <Button disabled={isLoading}>Generate</Button>

Show progress and disable controls during async operations.

DON'T
// Don't show only a spinner {isGenerating && ( <Loader2 className="animate-spin" /> )} // Don't allow actions during loading <Button onClick={generate}> {isLoading ? 'Loading...' : 'Generate'} </Button> // ^ Still clickable!

Never hide progress or allow duplicate operations.

Pattern Consistency

DO
// Follow established patterns <span className="text-[9px] font-bold uppercase tracking-widest text-indigo-400 bg-indigo-500/10 px-2 py-0.5 rounded-lg"> STATUS </span> // Consistent button style <Button className="h-10 rounded-xl bg-indigo-500 text-white font-bold uppercase tracking-widest text-[10px]"> ACTION </Button>

Copy exact patterns from existing components.

DON'T
// Don't create variations <span className="text-xs italic text-blue-300 bg-blue-400/15 px-3 py-1 rounded-md"> status </span> // Don't mix styles on same component type <Button className="rounded-lg">Button 1</Button> <Button className="rounded-full">Button 2</Button> <Button className="rounded-sm">Button 3</Button>

Don't create style variations. One pattern per component type.
